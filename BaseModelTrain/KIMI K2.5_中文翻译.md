## 摘要

我们推出 Kimi K2.5，一个开源多模态智能体模型，旨在推进通用智能体智能。K2.5 强调文本与视觉的联合优化，使两种模态相互增强。这包括一系列技术：文本-视觉联合预训练、零视觉 SFT（Zero-Vision SFT）以及文本-视觉联合强化学习。在此多模态基础上，K2.5 引入了 **Agent Swarm**——一个自主并行智能体编排框架，能够将复杂任务动态分解为异构子问题并并发执行。广泛评测表明，Kimi K2.5 在编程、视觉、推理和智能体任务等多个领域达到了 SOTA（当前最优）水平。Agent Swarm 还将延迟相比单智能体基线降低了最多 **4.5 倍**。我们发布了后训练的 Kimi K2.5 模型检查点，以促进智能体智能的未来研究和实际应用。

模型地址：https://huggingface.co/moonshotai/Kimi-K2.5

## 1 引言

大语言模型（LLM）正快速向智能体智能演进。近期进展如 GPT-5.2、Claude Opus 4.5、Gemini 3 Pro 和 Kimi K2-Thinking，在工具调用和推理方面展示了实质性进步。这些模型越来越能够将复杂问题分解为多步骤计划，并执行交错的推理与行动序列。

在本报告中，我们介绍 Kimi K2.5 的训练方法和评测结果。相比前代模型，K2.5 在以下两个关键方面改进了训练：

### 1.1 文本与视觉的联合优化

K2.5 的一个关键洞察是：**文本与视觉的联合优化能同时增强两种模态，避免冲突**。具体技术包括：

- **预训练阶段**：与常规方法（在训练后期阶段将视觉 token 添加到文本骨干中）不同，我们发现**早期视觉融合搭配较低比例**在固定总视觉-文本 token 预算下效果更佳。因此，K2.5 在整个训练过程中以恒定比例混合文本和视觉 token。
- **架构上**：采用 MoonViT-3D——一个原生分辨率视觉编码器，融合 NaViT 打包策略，支持可变分辨率图像输入。对于视频理解，引入轻量级 3D ViT 压缩机制：连续四帧为一组，通过共享 MoonViT 编码器处理，并在 patch 级别进行时间平均。这一设计使 K2.5 能在相同上下文窗口内处理最多 **4 倍**长度的视频，同时保持图像和视频编码器间的完整权重共享。
- **后训练阶段**：提出**零视觉 SFT**——仅使用纯文本 SFT 即可激活视觉推理和工具使用。我们发现添加人工设计的视觉轨迹反而损害泛化性。随后对文本和视觉任务联合应用 RL。关键发现是：**视觉 RL 不仅没有降低文本性能，反而增强了文本性能**（MMLU-Pro 和 GPQA-Diamond 均有提升）。这种双向增强——"文本引导视觉，视觉反哺文本"——代表了联合训练中卓越的跨模态对齐。

### 1.2 Agent Swarm：并行智能体编排

现有智能体模型依赖顺序执行工具调用。即使是能执行数百个推理步骤的系统（如 Kimi K2-Thinking），也存在推理时间的线性扩展问题，导致不可接受的延迟。

Kimi K2.5 引入 **Agent Swarm**——一个动态并行智能体编排框架，并提出 **并行智能体强化学习（PARL）** 范式。与传统智能体 RL 不同，模型配备了子智能体创建和任务委派接口。训练时子智能体被冻结，其执行轨迹排除在优化目标之外；仅编排器通过 RL 更新。这种解耦规避了端到端协同优化的两大挑战：**信用分配模糊**和**训练不稳定**。

在广搜索场景中，Agent Swarm 将推理延迟降低最多 **4.5 倍**，同时将 item-level F1 从 72.8% 提升至 79.0%。

## 2 文本与视觉的联合优化

Kimi K2.5 是基于 Kimi K2 构建的原生多模态模型，在约 **15 万亿**混合视觉和文本 token 上进行大规模联合预训练。

### 2.1 原生多模态预训练

核心设计问题：**给定固定的视觉-文本 token 预算，最优的视觉-文本联合训练策略是什么？**

常规做法认为应在 LLM 训练后期以高比例（如 50%+）引入视觉 token。但我们的实验揭示了不同结论：

| 视觉注入时机 | 视觉:文本比例 | 视觉知识 | 视觉推理 | OCR | 文本知识 | 文本推理 | 编程 |
|---|---|---|---|---|---|---|---|
| 早期 | 10%:90% | 25.8 | 43.8 | 65.7 | 45.5 | 58.5 | 24.8 |
| 中期 | 20%:80% | 25.0 | 40.7 | 64.1 | 43.9 | 58.6 | 24.0 |
| 后期 | 50%:50% | 24.2 | 39.0 | 61.5 | 43.1 | 57.8 | 24.0 |

**结论：早期融合搭配较低视觉比例，在固定 token 预算下效果最好。** 这促使我们采用原生多模态预训练策略：在整个训练过程中持续以适度比例混合视觉数据，而非在末期集中进行视觉重型训练。

我们还观察到"**先降后升**"模式：中/晚期融合在引入视觉数据时，文本能力会暂时下降然后逐渐恢复。而早期融合在整个训练过程中保持更健康稳定的文本性能曲线。

### 2.2 零视觉 SFT

预训练的 VLM 不会自然执行基于视觉的工具调用，这对多模态 RL 构成冷启动问题。常规方法通过人工标注或提示工程 CoT 数据来解决，但多样性有限。

我们提出**零视觉 SFT**：仅使用文本 SFT 数据来激活视觉智能体能力。所有图像操作通过 IPython 中的编程操作代理，有效作为传统视觉工具使用的泛化。这种"零视觉"激活能产生多样化推理行为，包括像素级操作（如通过二值化和计数进行物体大小估计），并泛化到视觉定位、计数和 OCR 等任务。

实验表明：零视觉 SFT 足以激活视觉能力，同时确保跨模态泛化。相比之下，文本-视觉 SFT 在视觉智能体任务上表现更差，可能因为缺乏高质量视觉数据。

### 2.3 联合多模态强化学习

#### 基于结果的视觉 RL

零视觉 SFT 之后，模型需要进一步精炼以可靠地将视觉输入纳入推理。我们在三类任务上实施基于结果的 RL：

- **视觉定位与计数**：图像内物体的精确定位和枚举
- **图表与文档理解**：结构化视觉信息解读和文本提取
- **视觉关键的 STEM 问题**：筛选需要视觉输入才能正确解答的数学和科学问题

#### 视觉 RL 增强文本性能

出人意料的是，基于结果的视觉 RL 在纯文本基准上也产生了可测量的提升：

| 基准测试 | 视觉 RL 前 | 视觉 RL 后 | 提升 |
|---|---|---|---|
| MMLU-Pro | 84.7 | 86.4 | +1.7 |
| GPQA-Diamond | 84.3 | 86.4 | +2.1 |
| LongBench v2 | 56.7 | 58.9 | +2.2 |

分析表明，视觉 RL 增强了需要结构化信息提取领域的校准能力，减少了对类似视觉推理查询的不确定性。

#### 联合多模态 RL

K2.5 的后训练采用联合多模态 RL 范式：RL 领域不按输入模态组织，而是**按能力组织**——知识、推理、编程、智能体等。这些领域专家同时从纯文本和多模态查询中学习，生成式奖励模型（GRM）同样跨异构轨迹优化。这确保通过任一模态获取的能力提升自然泛化到增强另一模态的相关能力。

## 3 Agent Swarm

### 3.1 架构与学习设置

PARL 框架采用解耦架构：**可训练的编排器** + **冻结的子智能体**（从固定中间策略检查点实例化）。

设计动机：在多智能体设置中，基于结果的奖励本质上是稀疏且有噪声的——正确答案不保证子智能体完美执行，失败也不意味着所有子智能体出错。通过冻结子智能体并将其输出视为环境观测（而非可微分决策点），将高层协调逻辑与底层执行能力解耦，实现更稳健的收敛。

为提高效率，先用小型子智能体训练编排器，再过渡到更大模型。RL 框架还支持动态调整子智能体与编排器间的推理实例比例。

### 3.2 PARL 奖励

训练可靠的并行编排器面临延迟、稀疏和非平稳反馈的挑战。PARL 奖励定义为：

```
r_PARL(x, y) = λ₁ · r_parallel（实例化奖励）
             + λ₂ · r_finish（子智能体完成率）
             + r_perf(x, y)（任务级结果）
```

- **r_parallel**：缓解"**串行坍缩**"——编排器退化为单智能体执行。激励子智能体实例化，鼓励探索并发调度空间。
- **r_finish**：关注子任务成功完成。防止"**虚假并行**"——编排器通过大量生成子智能体来提高并行指标但不进行有意义的任务分解。
- **λ₁ 和 λ₂** 在训练过程中退火至零，确保最终策略优化主要目标。

### 3.3 关键步数作为资源约束

为衡量并行智能体设置中的计算时间成本，定义**关键步数**（类比计算图中的关键路径）：

```
CriticalSteps = Σ_{t=1}^{T} [ S_main(t) + max_i S_sub,i(t) ]
```

每个阶段 t 的持续时间由该并行组中最慢的子智能体决定。通过关键步数而非总步数约束训练和评估，框架明确激励有效并行化：过多的子任务创建若不缩短最长并行分支的执行时间，则收益甚微。

### 3.4 并行智能体能力诱导的提示构建

为激励编排器利用并行化优势，构建合成提示以压力测试顺序智能体执行的极限：

- **广搜索**：需要同时探索大量独立信息源
- **深搜索**：需要多个推理分支和延迟聚合
- **真实世界工作负载**：长上下文文档分析、大规模文件下载等

这些提示不明确指示模型并行化，而是塑造任务分布使并行分解和调度策略自然受到偏好。

## 4 方法概述

### 4.1 基础模型：Kimi K2

Kimi K2.5 的基础是 Kimi K2——一个**万亿参数混合专家（MoE）** Transformer 模型，在 15 万亿高质量文本 token 上预训练。

- 总参数：**1.04 万亿**，激活参数：**320 亿**
- 384 个专家，每 token 激活 8 个（稀疏度 48）
- 使用 MuonClip 优化器 + QK-Clip 保证训练稳定性

### 4.2 模型架构

多模态架构由三部分组成：
1. **MoonViT-3D**：三维原生分辨率视觉编码器
2. **MLP 投影器**：连接视觉编码器和 LLM
3. **Kimi K2 MoE 语言模型**

**MoonViT-3D** 的设计要点：
- 基于 SigLIP-SO-400M 初始化
- 采用 NaViT 的 patch 打包策略，支持任意分辨率
- 将"patch n' pack"理念推广到时间维度：最多 4 帧连续帧被视为时空体积，联合展平打包为单个 1D 序列
- 图像和视频共享同一注意力机制和参数空间
- 轻量级时间池化实现 **4 倍时间压缩**，显著延长可处理视频长度

### 4.3 预训练流程

| 阶段 | 数据 | 序列长度 | Token 量 | 训练参数 |
|---|---|---|---|---|
| ViT 训练 | Alt text、合成描述、定位、OCR、视频 | 4096 | 1T | ViT |
| 联合预训练 | 文本、知识、交错、视频、OS 截图 | 4096 | 15T | ViT & LLM |
| 联合长上下文中训 | 高质量文本和多模态、长文本、长视频、推理、长CoT | 32768→262144 | 500B→200B | ViT & LLM |

**ViT 训练阶段**：从 SigLIP 持续预训练，仅使用交叉熵损失（无对比损失）。两阶段对齐策略：(1) 更新 MoonViT-3D 对齐至 Moonlight-16B，约 1T token；(2) 仅更新 MLP 投影器，桥接 ViT 与 LLM。

**联合训练阶段**：从接近末端的 K2 检查点继续，额外 15T 视觉-文本 token。数据配方增加编程内容权重，控制每数据源最大 epoch。第三阶段通过 YaRN 插值逐步延长上下文。

### 4.4 后训练

#### 4.4.1 监督微调（SFT）

沿用 K2 的 SFT 流程，从 K2、K2 Thinking 和内部专家模型合成高质量候选响应。数据生成策略结合人工标注、提示工程和多阶段验证，产出大规模指令微调数据集。

#### 4.4.2 强化学习

**策略优化**：对每个问题 x 从数据集 D 采样，生成 K 个响应。优化目标引入了** token 级别裁剪机制**，通过梯度掩码缓解训练与推理框架间的 off-policy 偏差。与标准 PPO 裁剪不同，该方法严格依赖 log-ratio 来显式限制 off-policy 漂移。

**奖励函数**：
- 可验证任务：基于规则的结果奖励
- 资源优化：预算控制奖励提升 token 效率
- 通用任务：生成式奖励模型（GRM）
- 视觉任务：定制奖励（定位用 F1+IoU 软匹配、分割用栅格化 IoU、OCR 用归一化编辑距离、计数用绝对差值）

**生成式奖励模型（GRM）**：不仅作为二元裁判，而是与 Kimi 价值观对齐的细粒度评估器，涵盖有用性、响应就绪度、上下文相关性、细节适当程度、生成工件美学质量、严格指令遵循等。使用多种替代 GRM 评分标准缓解奖励黑客攻击。

**Token 高效强化学习——Toggle**：

观察到"**长度过拟合**"现象：在刚性预算约束下训练的模型无法有效利用额外推理时间 token。提出 **Toggle** 训练启发式方法，在推理时间扩展和预算约束优化之间交替：

- **Phase 0（预算限制阶段）**：在任务相关 token 预算内训练。仅在模型对给定问题的平均准确率超过阈值 λ 时施加约束
- **Phase 1（标准扩展阶段）**：允许模型生成至最大 token 限制，鼓励利用计算获得更好的推理时间扩展

预算根据正确响应子集中的 ρ 百分位 token 长度估算，训练开始时固定。在 K2 Thinking 上评估，Toggle 平均减少输出 token **25~30%**，性能影响微乎其微。冗余模式（如重复验证和机械计算）大幅减少。Toggle 还表现出强领域泛化——仅在数学和编程任务上训练，在 GPQA 和 MMLU-Pro 上也实现了 token 缩减。

### 4.5 训练基础设施

#### 解耦编码器流程（DEP）

传统多模态训练中，视觉编码器和文本嵌入共存于流水线第一阶段（Stage-0），因多模态输入大小变化导致计算和内存负载剧烈波动。

DEP 由三个阶段组成：

1. **均衡视觉前向**：视觉编码器在所有 GPU 上复制，前向计算工作负载基于负载指标均匀分布。丢弃所有中间激活，仅保留最终输出。结果回传至 PP Stage-0。
2. **骨干训练**：执行主 Transformer 骨干的前向和反向传播，可完全复用纯文本训练验证的高效并行策略。
3. **视觉重计算与反向**：重新计算视觉编码器前向，然后反向传播计算梯度。

DEP 实现了负载均衡，解耦视觉编码器和主骨干的优化策略，多模态训练效率达到纯文本训练的 **90%**。

#### 硬件配置

- NVIDIA H800 GPU 集群，8×400 Gbps RoCE 跨节点互联
- 16 路流水线并行（PP）+ 16 路专家并行（EP）+ ZeRO-1 数据并行
- 选择性重计算（LayerNorm、SwiGLU、MLA 上投影）
- 激活压缩至 FP8-E4M3
- 激活卸载至 CPU（带重叠流式传输）

#### 执行时间节省

在 WideSearch 上，Agent Swarm 将达到目标性能所需的执行时间减少 **3~4.5 倍**。随着目标 F1 从 30% 升至 70%，单智能体执行时间从 1.8 倍增长到 7.0 倍以上，而 Agent Swarm 保持在 0.6~1.6 倍的近恒定低延迟。

#### Agent Swarm 作为主动上下文管理

与被动的上下文截断策略（Hide-Tool-Result、Summary、Discard-all）不同，Agent Swarm 实现了**主动上下文控制**：

- 长时任务被分解为并行的、语义隔离的子任务
- 每个子智能体维护独立工作记忆，执行局部推理
- 仅任务相关输出（而非完整交互轨迹）选择性回传给编排器
- 这实现了"**上下文分片**"而非上下文截断

### 5.5 定性示例

**黑神话：悟空完整通关分析**（Figure 11）：
- 24 小时连续游戏视频，32 个 1080p 视频，共 40GB
- Agent Swarm 采用层级多智能体架构：主智能体编排 32 个并行子智能体
- 每个子智能体独立处理一段视频：帧提取、时间事件分析、关键时刻识别
- 主智能体聚合分析结果，合成包含时间线、视频片段和交互式可视化的 HTML 展示页面

**视觉推理任务示例**（Figure 12）：
1. **迷宫求解**：二值化图像分割 + BFS 寻路算法，3288 步路径
2. **饼图分析**：HSV 色彩空间像素级分割，精确计算面积比例
3. **找不同**：像素级差异检测，自动识别 10 处主要差异

## 6 结论

Kimi K2.5 证明了可扩展的通用智能体智能可以通过文本与视觉联合优化以及并行智能体执行来实现。通过在预训练和强化学习中统一语言和视觉，模型实现了强跨模态对齐和视觉-文本推理。Agent Swarm 实现异构子任务的并发执行，在降低推理延迟的同时提升复杂智能体工作负载的性能。通过开源后训练检查点，我们旨在支持开源社区构建可扩展的通用智能体系统，加速迈向通用智能体智能（General Agentic Intelligence）。

### 附录 B：预训练数据

### 附录 D：统一智能体强化学习环境

- 标准化 Gym 接口，支持黑盒/白盒环境

- Token-in-Token-out 范式，记录所有推理引擎输出的 log 概率进行训练-推理不匹配校正

### 附录 E：评测设置详情
