# GenRec：Netflix 基于 LLM 的推荐排序器

> **原文**: GenRec: An LLM-Backed Recommendation Ranker at Netflix

> **作者**: Ying Li, Shradha Sehgal, Arjun Rao, Rein Houthooft, Yunan Hu, Yaochen Zhu, Sourabh Medapati, Yun Li, Linas Baltrunas, Grace Huang, Ashish Rastogi, Kamelia Aryafar（Netflix / Amazon）
> **链接**: https://arxiv.org/abs/2608.10257

## 摘要

大语言模型（LLM）正在重塑推荐系统，它使我们能够直接以自然语言对用户、内容和上下文进行更丰富的建模。在 Netflix，我们正通过 **GenRec** 探索这一方向——这是一个构建在自研基础 LLM 之上的、以 LLM 为底座的推荐排序器。GenRec 遵循**两阶段框架**：阶段 1 将一个开源 LLM 适配到 Netflix 数据上，使其对 Netflix 的内容目录（catalog）和会员行为建立深入理解，同时兼顾内容理解与指令跟随等能力；阶段 2 在该基础模型之上，使用推荐排序专用的数据、标签和奖励信号进行后训练（post-training），目标是让排序器与业务需求以及长期会员满意度对齐。

本文聚焦于阶段 2，以及从拥有数千个手工工程特征的**传统判别式排序器**，向由"语言化（verbalized）的用户历史与上下文"驱动的 **LLM 排序器**的转变。我们介绍了输入语言化与上下文工程（context engineering）的设计、后训练数据构造、奖励整合、模型架构，以及基于 **prefill-only 推理**的成本受限服务方案。我们报告了大规模 A/B 测试的结果：在与当前生产排序器的对比中，使用远少于阶段 2 有标注训练样本和输入信号的 GenRec 模型，在离线与在线指标上均取得了统计显著的提升。我们还讨论了 LLM 排序器可能带来的推荐范式转变：从特征工程到上下文工程，从定制架构到共享的基础模型骨干。最后，我们总结了在真实资源约束下服务此类系统的实践经验。

## 1 引言

推荐系统是 Netflix 数亿会员体验的核心。我们当前生产环境的推荐系统基于大量横跨用户、物品和交互信号的手工特征，以及大量高阶特征交互来生成个性化推荐，这与以往的大规模推荐系统一致 [3, 4, 11, 15]。它们还采用了为不同推荐需求量身定制的复杂架构：例如用于建模特征交互的专用网络、用于捕捉动态会员兴趣的 Transformer 架构，以及支撑多个推荐任务的多任务学习架构 [10, 14, 27, 28]。

这些模型经过多年迭代，为 Netflix 产品中多种内容类型（电影、剧集、游戏、直播、播客等）生成推荐。虽然这套架构已成为会员体验的关键组成部分，但支持新的业务需求变得越来越困难。例如，接入一种新的内容类型或新的推荐场景（surface），往往需要在特征工程、模型架构设计、基础设施变更和实验方面投入大量工作。因此，系统的复杂性使其难以跟上 Netflix 业务需求的快速增长。

近来，大语言模型（LLM）开始重塑整个行业中推荐系统的设计、部署与使用方式 [9, 13, 23]。它们广博的世界知识和强大的语言理解能力，使得对用户、内容和上下文的建模比传统架构更加丰富。这为下一代推荐系统开辟了新的可能性：将用户历史与上下文信号直接表示为自然语言，凭借对用户偏好和物品语义更深的理解来生成更好的推荐。它也使新用例的适配更加迅速——例如通过 prompt 引导推荐，而无需重新设计新的专用模型和流水线。

然而，开箱即用的 LLM 还不能直接胜任生产级推荐器：它们倾向于过度推荐全球热门内容、幻觉出目录之外的片名、忽略细微的业务约束，且个性化程度有限。为解决这些问题，我们构建了 **GenRec**——一个在 Netflix 语料上对内部基础 LLM 进行后训练的 LLM 推荐排序器。具体来说，我们聚焦于**全目录排序（full-catalog ranking）**用例，并证明基于 LLM 的推荐排序器是一条可行且有前景的路径。GenRec 代表了我们从传统推荐栈向 **LLM 原生系统**过渡的第一步。

使用 GenRec 生成推荐时，我们首先将用户交互历史、物品元数据和上下文信息语言化为自然语言，然后将这一文本表示分词后输入 LLM（图 1）。为了让模型学习 Netflix 特有的用户偏好并避免过度推荐热门物品，我们在 Netflix 的目录与会员行为数据上对模型进行后训练。我们通过在训练中引入多个奖励信号，使推荐输出与长期会员满意度和业务目标对齐。我们进一步将模型输出约束在 Netflix 目录内的物品上，使模型具备"目录感知（catalog-aware）"能力，从而消除目录外的推荐。最后，我们在成本约束下优化 GenRec，并将其接入 Netflix 的 LLM 服务栈。

与现有的生产推荐排序器相比，GenRec 大幅简化了特征工程。我们不再人工设计复杂的特征交互，而是依赖 LLM 直接从原始输入文本中推断这些交互和用户偏好。这将推荐问题从**特征工程**转变为**上下文工程**：决定向模型呈现哪些信息、如何在有限的 token 预算内表达这些信息、以及优化什么目标和奖励——而不是迭代式地设计和集成新特征与特征交互。

GenRec 还受益于预训练基础 LLM 已具备的能力（例如用户理解和内容理解），因此无需从零构建这些能力。因此，我们观察到 GenRec 只需要远少于传统模型的阶段 2 有标注样本和输入信号，就能达到与成熟生产排序器相当的水平。这种阶段 2 后训练阶段的边际数据效率尤其有价值：因为阶段 1 基础训练的更新频率低得多，而阶段 2 模型的刷新频率要高得多。

我们通过离线实验和大规模在线 A/B 测试，将 GenRec 与成熟的生产基线进行对比评估。在测试的配置中，GenRec 仅使用了当前生产栈阶段 2 有标注训练数据和输入信号的一小部分，却在离线和在线指标上均取得了统计显著的提升，同时降低了对人工工程特征和定制架构的依赖。总之，这些结果表明：至少在所测试的推荐场景上，LLM 排序器是传统模型可行且有前景的替代方案。

本文的贡献包括：

- **与成熟生产系统具有竞争力的 LLM 排序**。我们提出 GenRec——构建在自研基础 LLM 之上的 LLM 推荐排序器，并将其与一个长期运行、高度工程化的生产排序器对比。使用远少于阶段 2 训练样本和输入信号的 GenRec 模型，在我们主要的离线和在线指标上取得了统计显著的提升。
- **两阶段、以 LLM 为中心的训练框架，并量化了各阶段的收益**。我们验证了两阶段训练方案：阶段 1 将开源 LLM 适配到 Netflix 数据以构建 Netflix 领域感知的基础模型；阶段 2 进行高频更新的推荐排序后训练。我们阐明了两阶段各自的角色与目标，并实证分解了它们对排序质量的影响，显示两个阶段都带来了显著收益。
- **带目录感知打分的 LLM 排序架构**。我们描述了一种架构：使用生成式的 decoder-only LLM 骨干，配合一个目录感知打分头（catalog-aware scoring head），在单次前向传播中为大型物品目录打分。这一设计既支持大候选集排序，又将推荐限制在目录内物品上。
- **上下文工程与奖励加权训练作为质量-成本控制的实用杠杆**。我们将上下文工程与奖励整合视为一等公民的设计维度。在上下文侧，我们展示了精心的语言化设计可以把有效上下文长度压缩到原始 token 预算的**约三分之一**，而离线排序质量几乎无损，服务成本也随之获得相近倍数的下降。在目标侧，我们通过**奖励加权排序损失**整合多个奖励信号，以稳健且低成本的方式引导模型趋向长期价值和业务目标。
- **关于数据/模型扩展与质量-成本权衡的实证观察**。我们刻画了推荐质量随阶段 2 后训练数据量与骨干模型规模的变化规律，以及这些收益与训练、服务成本之间的相互作用。我们观察到跨模型尺寸一致、单调的数据扩展行为，并为阶段 2 配置在质量-成本 Pareto 前沿上识别出实用的"最优点（sweet spot）"。这些发现为在资源约束下设计 LLM 推荐器提供了可操作的指导。

本文其余部分组织如下：第 2 节将我们的工作置于生成式与 LLM 推荐的现有研究之中；第 3 节形式化问题设定；第 4 节介绍方法论，包括输入语言化、模型架构、后训练数据与奖励、服务优化；第 5 节给出离线实验和大规模在线 A/B 测试结果；第 6 节讨论 LLM 原生推荐可能带来的转变；第 7 节总结全文并展望未来工作。

## 2 相关工作

### 2.1 基于特殊 token 的生成式推荐

一系列不断增长的工作将推荐建模为在用户交互序列上的自回归生成。SASRec [10] 和 BERT4Rec [21] 等序列推荐器通过物品 ID 序列上的下一物品预测确立了这一模板。工业界随后用 transformer-decoder 骨干扩展了这一范式，其词表被扩展出编码物品 ID、物品元数据、地区、时间、设备、场景等信息的特殊 token，使模型能够以异构信息为条件 [1, 16, 25]。

一个互补的方向是将物品 token 化为语义编码，以捕捉物品的语义信息。例如 TIGER [19] 将每个物品表示为一小段"语义 ID（Semantic ID）"序列——通过对内容嵌入做 RQ-VAE 学习得到——从而支持在十亿级目录上自回归解码。该方法的多个变体已在多个平台落地，包括 Google 的排序 [20] 和快手的端到端检索-排序 [6]。

这些模型表现出很强的性能，但它们在利用广博世界知识、通过灵活 prompt 引导推荐、或继承现代预训练语言模型更丰富能力方面通常受限。这些局限推动了一条平行的工作线：直接在 LLM 骨干之上构建推荐器。

### 2.2 基于 LLM 的推荐

大语言模型在各类任务上的成功，启发了一系列用预训练 LLM 作为推荐器骨干的工作——而不是从零开始训练带特殊 token 的推荐专用 transformer。早期学术系统将推荐建模为语言模型之上的文本到文本生成 [2, 7, 24]。

为了让 LLM 能直接生成物品而非自由文本，近期工业界系统用 **Semantic-ID 物品 token** 扩展 LLM 词表。Google 的 PLUM [8] 在 YouTube 规模上通过 Semantic-ID token 化、领域数据上的持续预训练和任务特定的微调来适配预训练 LLM。Spotify 的 GLIDE [5] 将播客发现表述为对 Semantic-ID 目录的指令跟随。快手的 OneRec-Think [12] 用 Qwen3 模型骨干和推理步骤扩展了 OneRec。

大多数基于 LLM 的生成式检索系统在推理时依赖自回归解码加 beam search，这引入了延迟开销，在大规模尤其是大候选集场景下可能令人望而却步。我们的工作通过为基座 LLM 架构增设**目录感知排序头**来规避这些限制，使其能在单次前向传播中完成大候选集排序，令服务更具成本效益。此外，我们明确地以 LLM 视角设计整个系统，包括有效的上下文工程与奖励整合，以在真实资源约束下满足业务需求并优化长期用户满意度。

## 3 问题设定

在 GenRec 中，我们关注**全目录排序**问题（若给定候选集，则为 top-K 排序）。得到的排序列表可作为用户偏好的个性化表示，在多种用例中复用，包括各种场景下的物品排序，以及作为下游应用的个性化输入信号。

**记号**。令 $U$ 表示用户集合，$C$ 表示物品目录（电影、剧集、游戏、直播、播客等），$X$ 表示上下文空间（设备、场景、地区、时段等）。这里我们考虑单次推荐请求，由用户 $u \in U$、上下文 $\tau \in X$ 和时间 $t$ 刻画；令 $H$ 表示该用户在 $t$ 之前的交互历史。每个物品 $i \in C$ 关联元数据 $M_i$（片名、类型、简介、上映日期等）。

**排序目标**。推荐器将请求 $(u, \tau, t, H)$ 映射为目录 $C$ 的一个排序 $\pi: C \to \{1, ..., |C|\}$，其中 $\pi(i)$ 表示物品 $i$ 被分配的位置（rank 1 位于列表顶端）。目标是选择使**期望长期会员效用**最大化的排序 $\pi$——它是会员满意度与留存的代理指标——而不仅仅是短期互动。

## 4 方法论

### 4.1 总览

GenRec 遵循**两阶段训练框架**（图 2）。阶段 1 在开源（OSS）模型之上，用 Netflix 专有数据训练一个基础 LLM，使其对 Netflix 用户与内容建立深入理解。阶段 2 在该基础模型之上，用排序应用专用的数据和目标进一步后训练，产出针对推荐排序任务定制优化的 GenRec。

> **图 2：两阶段训练框架**。阶段 1 在 Netflix 数据上训练基础 LLM 以获得用户与内容理解；阶段 2 在推荐排序专用数据与目标上进行后训练。

与阶段 1 相比，GenRec 阶段 2 后训练追求几个不同的目标：

1. **能力侧重**：阶段 1 优化并平衡一组广泛的基础能力，如世界知识、个性化能力、内容理解和语言能力。相比之下，阶段 2 更聚焦于推荐排序能力，如排序质量和推荐引导（steering）。
2. **更新节奏**：阶段 1 更新相对低频，面向长期的用户/内容理解和语言能力；阶段 2 需要更频繁地更新，以追踪新内容上线、不断变化的流行度模式和会员最新兴趣。
3. **成本敏感度**：阶段 1 旨在构建能力最强的基础模型，受服务成本约束较小；而阶段 2 必须显式地做到成本高效，以服务大规模流量。

### 4.2 后训练数据

在 Netflix，会员在电影、剧集、游戏、直播等多种内容类型上产生**数千亿**次交互事件。这些交互覆盖广泛的互动信号——观看、游玩、点赞（thumb）、加入清单等——并发生在多个推荐场景上。

为了后训练出具备推荐能力的 LLM，我们把会员的历史交互数据转化为用户与推荐器之间的单轮或多轮"对话"。每一轮将一条**用户消息**（融合上下文、历史和任务）与一条代表该轮会员真实互动的**助手消息**配对。具体来说，每段对话包含：

- **上下文**：场景（surface）、时间、设备、地区等；
- **用户画像与历史**：国家、会龄、订阅套餐、历史交互等；
- **物品级细节**：物品 ID、物品元数据（片名、上线时间、简介等）、流行度趋势等；
- **任务**：例如预测用户接下来会观看或点赞的物品；
- **助手消息**：用户的隐式或显式反馈（播放、播放时长、弃剧、点赞等），作为训练期间的真实标签（ground-truth）信号。

在阶段 2 后训练期间，LLM 在这类对话数据上被优化，建模助手消息如何依赖于之前的用户消息。这种对话式框架提供了一种统一的方式，把丰富的推荐日志表达为文本，随后既用于训练语言建模目标，也用于训练"模型架构"一节所述的目录感知排序目标。

### 4.3 输入语言化与上下文工程

传统推荐器将用户交互与物品元数据编码为手工特征或稠密嵌入，与之不同，GenRec 将丰富的用户交互历史与上下文**语言化（verbalize）**为自然语言或轻结构化文本。通过将原始交互信号直接编码进 LLM 的语义空间，GenRec 依赖 LLM 学习更高阶的模式——如物品关系、时间动态和演化的用户兴趣——而不是通过人工特征工程显式编码这些关系。

语言化绝不仅仅是把信号转成文本；它需要深思熟虑的**上下文工程** [18]，以便在有限的 token 预算内容纳很长的用户上下文。会员的交互历史很容易超出 token 预算，原因既在于交互数量庞大，也在于每次交互的元数据很丰富。上下文窗口是有限且宝贵的资源：过长的上下文会稀释注意力，并显著增加训练与推理成本。

因此，我们精心筛选哪些事件和属性进入上下文窗口：

- **完整保留**：高信号互动（如长时长播放、点赞事件）用更丰富的元数据语言化；
- **完全省略**：近期低信号事件——如极短时长的播放或有噪声的浏览/点击——直接省略，因为相对于其 token 成本，它们对排序质量的贡献很小；
- **摘要或压缩**：重复性行为（如连刷/binge-watching）被压缩，而不是逐一罗列每个事件；
- **选择性详述**：对重要物品（如新片或冷启动物品），可以纳入更详细的元数据，以弥补预训练模型与历史交互中可用信息的不足。

在固定 token 预算内，我们优先以更高粒度保留中短期历史，而更久远的历史要么省略、要么压缩为简短的用户兴趣摘要。总体目标是构造一组紧凑而高信息量的 token，在不超出上下文窗口、不产生过高推理成本的前提下保住推荐质量。

### 4.4 后训练目标

GenRec 阶段 2 训练主要结合两个目标：

1. **推荐排序目标**。主任务是一个目录感知排序目标，训练模型为对应高价值互动的物品打更高分。在该任务中，正样本对应高质量互动事件（如高时长播放、强显式反馈），并配有按内容类型区分的去噪逻辑和阈值。这些标签用于目录（或候选集）上的交叉熵损失，教会模型在给定语言化上下文的情况下产出高质量的物品排序。
2. **语言建模目标**。此外，我们在语言化的输入和输出（如预测出的片名和其他文本字段）上加入语言建模目标。该任务帮助保持骨干模型通用的语言理解与文本生成能力，这对 (i) 建模丰富的自然语言用户历史与物品元数据、(ii) 支持通过 prompt 引导推荐，都很重要。

**训练时**，模型被联合优化以 (i) 为物品打分排序，(ii) 建模文本领域（例如预测片名和语言化上下文中的 token）。**推理时**，我们目前只用排序任务来生成推荐排序。语言建模目标主要用于：为排序任务引入互补的文本信息、保持语言理解和对 prompt 引导的响应能力，并为未来的文本生成用例（如自然语言解释）保留可能性。

整体 GenRec 模型用一个多目标损失训练，融合推荐排序目标、语言建模目标以及其他适用的目标：

$$L = \alpha \cdot L_{\text{ranking}} + \beta \cdot L_{\text{language}} + \gamma \cdot L_{\text{miscellaneous}}$$

$$\text{s.t. } \alpha + \beta + \gamma = 1, \quad \alpha, \beta, \gamma \geq 0$$

其中 $\alpha, \beta, \gamma$ 是可调超参数，可通过离线实验调节。

### 4.5 模型架构

GenRec 的骨干架构与基础 LLM 保持一致：一个用下一 token 预测式目标训练的 **decoder-only Transformer**。它被增设一个**目录感知排序头**，将推荐约束在 Netflix 目录内物品上，并支持大候选集上的高效打分。

**打分模型**。打分通过以下三个阶段计算：

1. **语言化**。语言化器 $V$ 将交互历史、上下文和物品元数据映射为单一文本序列：
   $$x = V(H, \{M_i\}_{i \in C}, \tau) \tag{1}$$
2. **池化表示**。LLM 将 $x$ 编码为一个 $d$ 维表示 $h$，取自某个池化位置的隐状态，汇总了用户偏好与上下文。
3. **目录感知打分**。打分头 $\phi$ 将 $h$ 与每个物品学到的 $d$ 维嵌入 $e_i$ 结合，为每个物品 $i$ 打分，作为推荐排序任务。

参数 $\theta$——包括 LLM 权重、打分头 $\phi$ 和物品嵌入 $\{e_i\}$——被联合训练。目录上的 softmax 将这些分数转换为概率分布，随后可由物品分数导出目录排序 $\pi$。当目录过大而无法全量打分时，可以将打分与 sampled-softmax 结合使用。

### 4.6 奖励信号

除了原始推荐准确率，GenRec 还必须满足两个额外目标：

1. **尊重业务需求**，例如内容混排逻辑（平衡电影、剧集、直播、游戏、播客等内容类型）；
2. **最大化长期会员满意度**，而不仅仅是优化短期用户互动。

只在原始交互序列上做后训练，有偏离这些目标的风险。例如，模型可能过度推荐连刷行为而非探索新内容、偏爱视频而冷落游戏、或选择那些以牺牲目录探索和长期留存为代价最大化即时点击的物品。为此，我们将来自独立奖励模型的奖励信号纳入 GenRec 的训练目标。我们使用两大类奖励：

1. **长期满意度代理指标**。这类奖励估计一次短期互动事件与长期结果的关联强度。由于真实的长期指标噪声大且滞后，我们依赖从历史数据学到的更稳定的代理。例如，奖励模型会给予那些鼓励会员回访服务、探索目录更广范围、或带来持续长期互动的事件更高价值。
2. **跨内容与互动类型的行为再平衡**。额外的奖励用于在内容类型（电影 vs 游戏 vs 直播 vs 播客）和上线阶段（预上线、新上线、长青内容）之间再平衡行为，以满足诸如各内容类型曝光公平性等业务目标。

我们利用既有奖励建模框架 [22] 中的多个奖励模型，通过**奖励加权排序损失**将其输出整合进 GenRec。具体来说，每个训练样本被赋予一个由多个奖励信号导出的标量权重，该样本的排序损失相应缩放。高价值互动（按奖励模型衡量）获得更大权重，低价值或不受欢迎的行为被降权。

这种奖励加权损失提供了一种简单、稳健且低成本的方式，引导模型趋向长期价值与业务对齐的行为。与完整的强化学习方法相比，该方法更易部署和维护。在初步实验中，RL 式方法（如 GRPO）相对监督微调展现出额外收益，但其高昂的训练开销更适合作为未来工作。因此，出于简洁性、稳定性和成本考虑，我们目前采用奖励加权损失作为 GenRec 的主要对齐机制。

### 4.7 在线服务与成本优化

GenRec 通过 Netflix 内部 LLM 服务栈（基于 vLLM 框架 [17]）提供服务。在 Netflix 的规模下（全球数亿会员），服务成本是一等约束，而推理成本在实践中大致与"模型大小 × 上下文长度"的乘积成正比。因此我们采取两条互补的降本策略。**第一，探索更小、经过蒸馏的语言模型** [26]——在更大或更有针对性的数据集上训练——力求在降低单请求计算量的同时恢复大模型的大部分质量。**第二，通过语言化压缩激进地优化上下文长度**（如前一节所述），在不显著降低离线排序质量的前提下减少表达输入信号所需的 token。

推理成本的另一个杠杆是**推理模式**。由于 GenRec 需要在很大的候选集上为物品排序，朴素的自回归解码（如逐 token 生成或 beam search）成本会高得离谱。尽管底层骨干是一个能够自回归解码的生成式 decoder-only LLM，我们有意识地将 GenRec 部署为 **prefill-only 配置**：模型一次性消费输入上下文，并在单次前向传播中产出整个候选集的排序。这避免了逐步解码，使我们能够在计算预算内于高吞吐负载上服务 GenRec。

## 5 实验与结果

本节将 GenRec 与生产模型对比，分析性能随数据与模型规模的扩展规律，量化阶段 1 与阶段 2 训练的贡献，并研究上下文长度优化的影响。

### 5.1 GenRec 与生产基线的对比

我们将 GenRec 与生产基线——一个经多年调优的成熟判别式模型——进行对比。

**离线**上，GenRec 在排序指标 MRR（Mean Reciprocal Rank，平均倒数排名）上超过生产模型，同时使用的阶段 2 训练数据和输入信号显著更少。具体来说，只用约为生产模型 **1/40** 的阶段 2 有标注训练样本，GenRec 在 MRR 上相对基线取得约 **+1.6%** 的离线提升。而且，随着进一步扩大训练数据和输入信号，离线指标还在持续改善。

我们在一次大规模在线 A/B 测试中验证了该结果，聚焦于关键的批计算（batch-compute）场景。我们分配了约 **10% 的 Netflix 流量，持续 4 周**。在低数据、低信号的配置下，阶段 2 GenRec 模型在短期和长期在线指标上均取得对生产基线统计显著的提升（见图 3）。例如，我们在核心在线指标上观察到 **+0.006%** 的相对提升——这在 Netflix 的规模下是有统计意义的。这些发现表明，LLM 排序器配合适当的后训练与奖励信号，可以成为传统推荐排序器可行且有前景的替代方案。

> **图 3：GenRec 与生产模型的在线指标**。短期首页互动指标：+0.115%（显著，P = 3.1 × 10⁻¹⁰）；长期核心指标：+0.006%（显著，P = 0.025）。GenRec 在短期和长期在线指标上均取得统计显著提升。

与生产排序器相比，GenRec 使用的训练样本数和输入信号相对较少，这体现了阶段 2 后训练的边际数据效率。由于阶段 2 的更新频率远高于阶段 1，提升这一阶段的数据效率在实践中尤其有价值——它直接降低了保持排序器时效性所需的计算量。

### 5.2 数据与模型规模扩展

**数据扩展**：我们首先研究推荐质量如何随阶段 2 后训练数据量扩展。固定其他变量，我们在从 1x 到 20x（以最小数据配置为基准）规模的数据集上训练 GenRec。我们对两种骨干规模开展该研究：较小模型（约 ~10 亿参数量级）和较大模型（约 ~100 亿参数量级）。对两种模型规模，我们都观察到离线排序指标 MRR 随阶段 2 数据量增加而**单调**提升（图 4）。尽管 ~1B 模型的绝对 MRR 低于 ~10B 模型，但它展现出与 ~10B 模型相似的扩展模式。

**模型扩展**：我们还考察了推荐质量随骨干规模的变化。在固定训练预算（相同 GPU 配置、相近的墙钟训练时间）下，我们对不同基座规模（约 ~1B 到 ~10B 参数量级）的几个 GenRec 变体进行后训练。在该约束下，更大的骨干一致地取得比小骨干更高的离线 MRR。

**阶段 2 的质量-成本权衡**：虽然数据和模型扩展都能提升质量，但它们也会增加训练与服务成本——对于以更高频率训练、并直接服务大规模线上流量的 GenRec 尤其如此。因此我们显式地搜索平衡质量与成本的阶段 2 配置：既要大到能捕获大部分增量质量收益，又不能大到让后训练或服务贵得离谱。实践中，我们利用数据与模型扩展曲线，配合上下文长度消融实验，在质量-成本 Pareto 前沿上识别一个"最优点"——在给定计算预算内恢复大部分可达到的质量提升。

### 5.3 阶段 1 与阶段 2 对推荐任务的影响

我们量化了阶段 1 基础训练与阶段 2 后训练对离线排序指标的贡献。

**阶段 1**。与直接用现成（off-the-shelf）LLM 作骨干相比，以阶段 1 基础 LLM 为基座可将离线排序指标提升约 **10-20%**。这凸显了从阶段 1 基础模型继承的个性化与内容理解能力的重要性。

**阶段 2**。在阶段 1 训练截止日期上评估时（即阶段 1 模型最新鲜的时候），阶段 2 后训练额外带来约 **35-50%** 的离线排序指标提升。这凸显了任务特定适配的价值，包括领域数据、奖励和语言化。此外，阶段 2 的相对收益随时间增长：两周后提升升至约 **80%**——这在预期之内。这一增长的收益既反映了任务特定适配的强度，也反映了更新频率较低的阶段 1 骨干日益陈旧（例如内容流行度趋势的变化和会员兴趣的演化）。

> **表 1：阶段 1 与阶段 2 训练的影响（离线排序指标 MRR）**
> - 阶段 1 的影响：相比用 OSS 模型作基座，**+10-20%**
> - 阶段 2 的影响：相比最新训练的阶段 1 模型，**+35-50%**，且收益随时间增长（两周后约 +80%）

### 5.4 上下文长度优化

LLM 的上下文窗口既是质量驱动因素，也是成本驱动因素：更长的语言化能暴露更多用户行为与上下文信息，但会增加训练与服务成本。因此，我们研究上下文长度和冗余度（verbosity）如何影响推荐表现，并显式搜索能在保住质量的前提下更紧凑的语言化方案。我们在"输入语言化与上下文工程"的启发式规则基础上分几步进行：

- **第一，做事件选择与压缩**。我们省略低信号或有噪声的互动、压缩重复活动、保留高信号交互。这产生一个清洗过的、有序的互动序列，作为进入上下文的候选。
- **第二，搜索最优的"详述历史长度"**。从这个清洗后的序列出发，我们改变保留在 prompt 中的历史事件数量。具体做法是扫描保留的互动数量，并绘制 MRR 随互动事件数变化的曲线。这揭示出一个**拐点（elbow point）**：在到达该点之前，质量随上下文长度增加而提升；超过该点后，额外的 token 只带来边际收益（图 5）。
- **第三，构造简洁高效的语言化**。对每个保留的事件，我们用不同细节层级构造 prompt（例如不同的互动细节、简化措辞、移除 few-shot 示例），并测量离线表现。

在我们的实验中，上下文长度可以压缩到原始 token 预算的**约三分之一**（例如从约 5,000 token 降到约 1,700 token），离线排序指标仅有可忽略的退化。这对应着上下文规模——以及推理成本——的大幅下降，同时模型质量基本不变。由于 GenRec 基本是计算受限的，服务成本近似与上下文长度成正比，我们观察到**服务成本也随之降到原来的约三分之一**。

## 6 讨论：LLM 原生推荐

GenRec 是 Netflix 迈向更以 LLM 为中心的推荐栈的第一步。从传统推荐系统走向基于 LLM 的系统，不只是"把排序器换成一个 transformer"：它改变了我们表示用户与内容的方式、构建模型与训练的方式，以及设计服务基础设施的方式。下面我们概述其中的若干转变及其在 GenRec 中的体现。合在一起，它们使我们的推荐栈更接近更广泛的 LLM 范式。

### 6.1 从特征工程到上下文工程

传统系统围绕大量手工特征构建，并由庞大的基础设施支撑特征聚合、新鲜度、交互设计和泄漏控制。相比之下，以 LLM 为中心的系统优先从原始交互序列、内容元数据、上下文、工具输出或用户记忆中构造丰富的文本上下文。**"prompt"成为新的特征向量**。建模的精力从设计单个特征转向上下文工程：决定包含哪些信号、如何摘要、回溯多远的历史、以及如何在有限 token 预算内编码。我们在语言化压缩上的实验体现了这一转变：精心的上下文设计可以在大幅降低服务成本的同时保住质量。

### 6.2 从定制架构到基础模型骨干

历史上，推荐系统依赖各式各样的定制架构——双塔模型、DLRM 式特征交互网络、自定义注意力模块，以及庞大的多任务体系。以 LLM 为中心的系统则标准化于从基础模型继承来的 transformer 骨干。创新上移了一个层级：从逐任务的架构设计，转向数据、扩展律（scaling laws）、后训练策略与推理优化等问题。

在 GenRec 中，我们复用与基础 LLM 相同的骨干，而不是从零设计新架构。这个 LLM 骨干还支持通过自然语言输入灵活地引导推荐，以支撑新的会员体验。

### 6.3 把扩展律作为设计指南

经典 RecSys 技术栈可能因稀疏 ID、重度工程化的目标和任务特定架构而遭遇收益递减。在 LLM 底座的设定下，推荐模型与预训练 LLM 共享骨干，并继承其数据与模型扩展行为。我们的研究显示了数据和模型尺寸两方面清晰的扩展趋势：性能随阶段 2 训练数据增加而单调提升，且在固定训练预算下更大模型一致优于小模型。这使 RecSys 更接近更广泛的 LLM 范式——在那里，扩展律被视为核心设计指南，而非事后观察。

### 6.4 预训练、后训练与奖励对齐

LLM 中心的方法不再从零构建每个推荐器，而是从一个预训练基础模型出发，再用任务特定的后训练和奖励对齐来适配这个共享骨干。在 GenRec 中，阶段 1 提供 Netflix 领域感知的基础 LLM，阶段 2 用标签、奖励和语言化做轻量的推荐专用适配。这一模式让创新更容易跨应用扩展：多个用例可以复用相同的基础和基础设施，而不是在彼此割裂的系统中重复实现相似的能力。

### 6.5 从 RecSys 基础设施到 LLM 基础设施

LLM 底座的推荐器必须处理更长的用户历史上下文，这使服务效率成为核心设计问题。同时，LLM 的训练与服务天然昂贵，因此成本优化必须主导模型尺寸、上下文长度和解码策略的选择。KV 缓存、前缀缓存（prefix caching）和 prefill-only 推理等技术，成为让推理在成本预算内可行的关键杠杆。其结果是，推荐的在线服务栈越来越像现代 LLM 基础设施——GPU 加速、基于 vLLM/Triton、精心做批处理与缓存——而不是围绕 MLP 或因子分解机构建的经典 RecSys 基础设施。

## 7 结论与未来工作

我们提出了 GenRec——Netflix 的 LLM 底座推荐排序器，并描述了如何将自研基础 LLM 适配为适合批计算场景生产流量的排序器。通过对用户历史与上下文的语言化、增设目录感知排序头、并用多个奖励信号训练，我们得到了一个 LLM 推荐器：尽管它使用的阶段 2 标签和显式输入信号远少于长期运行的生产排序器，但在我们研究的设定下，它在短期和长期在线指标上均取得了统计显著的提升。

总体而言，GenRec 代表了 Netflix 迈向更以 LLM 为中心的推荐栈的第一步。我们的结果表明，至少在某些场景下，这是大规模个性化的一条可行且有前景的路径——前提是我们继续谨慎地管理成本与基础设施复杂性，并持续以严格的评估对照强大的非 LLM 基线来权衡质量取舍。
